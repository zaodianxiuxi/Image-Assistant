# 图库父子层级与排序设计

## 目标

为图片合集提供稳定的父子数据结构：父级是系列，子级是故事节点；没有系列的图片统一归入“其他”，系列内没有节点的图片归入“未分配节点”。每个层级都携带可排序字段和图片自己的提示词快照。

## 数据结构

`GET /api/library/images` 返回的每条图片记录增加：`nodeId`、`nodeTitle`、`nodeOrder`。服务端从 `series_nodes` 左连接读取节点信息，保留没有节点的记录。

前端使用纯函数将记录整理为：

```text
GalleryGroup { key, title, seriesId, nodes[] }
GalleryNode { key, title, nodeId, nodeOrder, items[] }
```

父级 key 使用系列 ID；没有系列的记录使用固定 key `other`。节点 key 使用节点 ID；系列内没有节点的记录使用固定 key `unassigned`。

## 排序规则

- 父级按组内最近生成时间倒序，“其他”固定放最后。
- 有节点的子级按 `nodeOrder` 正序；缺少节点的“未分配节点”固定放最后。
- 子级图片按生成时间倒序，同一时间按记录 ID 倒序。

## 测试策略

新增静态图库夹具，覆盖多个系列、多个节点、无节点和无系列记录。测试纯分组函数的父子层级、唯一“其他”分组、节点顺序、图片时间排序及字段保留。数据库和图片文件不参与本阶段测试。

## 非目标

本阶段不调整图库 UI 布局、不增加折叠交互、不改变图片生成接口，也不改变图片提示词的存储方式。
