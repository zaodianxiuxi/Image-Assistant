# 可选数据库依赖设计

## 目标

未配置 MySQL 时，Image Assistant 仍可启动并使用图片生成、图片编辑、桌面图片保存和本地提示词热榜；只有数据库相关能力被禁用。配置 MySQL 后，提示词库、系列创作、故事节点和数据库图库继续按现有行为工作。

## 方案

将 `mysql2/promise` 从 `server/database.mjs` 的顶层静态导入改为按需动态导入。`getDatabase()` 先检查现有的 `MYSQL_HOST`、`MYSQL_DATABASE` 和 `MYSQL_USER` 配置；未配置时直接返回 `null`，不解析 `mysql2`。配置完整时动态加载依赖、创建连接池并执行现有迁移。

服务端路由不改变公开接口。已有数据库未配置时的返回语义保持不变：列表查询返回空列表，写入和需要数据库的操作返回明确的未配置错误；图片生成成功后的数据库记录保存仍然是尽力而为，不阻断本地图片落盘。

## 错误处理

- 缺少 `mysql2` 且未配置 MySQL：服务端正常启动。
- 配置了 MySQL 但缺少 `mysql2`：首次访问数据库能力时返回现有数据库错误，日志记录详细原因。
- MySQL 连接或迁移失败：保留现有错误处理和重试初始化行为。

## 测试

新增启动回归测试：在没有 `MYSQL_*` 配置的环境下启动服务端，并请求 `/api/health`，确认返回成功且 `databaseConfigured` 为 `false`。同时运行已有单元测试和生产构建，确保图片与提示词相关功能不回归。

## 非目标

本次不删除数据库路由、不修改数据库表结构、不引入替代存储，也不调整前端数据库功能的交互设计。
