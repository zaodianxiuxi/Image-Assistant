# 图片版本链与交付版本设计

## 目标

已生成图片可以直接进入编辑流程，编辑结果保留为新版本；同一创作对象下保留完整版本历史，并允许用户明确指定当前交付版本。

## 版本归属

- 有系列节点的图片：版本组归属于该系列节点。
- 没有系列的图片：首次继续编辑时创建独立版本组。
- 编辑已有历史图片时，新版本的父版本指向被编辑版本。
- 旧数据库记录没有版本信息时，第一次继续编辑会懒创建版本组并将旧图片作为第 1 版。

## 数据模型

新增 `image_version_groups` 表表示一次独立创作，保存系列/节点归属和当前交付版本 ID；新增 `image_versions` 表保存版本号、父版本、图片记录、提示词快照和是否交付。现有 `image_records` 保持不变，通过版本表关联。

新版本默认是候选版本，不自动成为交付版本。`POST /api/library/images/versions/:id/deliver` 在事务内清除同组旧交付标记并设置指定版本为当前交付版本。

## 前端流程

- 图片卡片提供“继续编辑”，下载本地图片并自动填入编辑模式。
- 编辑提交携带版本组和父版本信息；普通上传仍可创建新的版本组。
- 卡片显示版本号、交付标记和提示词摘要。
- 只有点击“设为交付版本”才改变交付标记；无数据库时在当前会话内完成同样操作。

## 无数据库行为

没有 MySQL 时，版本组和版本 ID 使用会话内生成的字符串保存于 React 状态；刷新页面后仍按现有规则丢弃会话历史，不伪造持久化数据。

## 测试

使用静态图片记录测试版本组继承、版本号递增、交付版本切换和提示词保留；使用源码/接口测试验证继续编辑控件、版本字段和交付接口。现有生成、编辑、图库和构建测试必须继续通过。
