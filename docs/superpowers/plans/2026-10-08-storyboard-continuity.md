# 故事分镜连续性优化实施计划

**目标：** 在系列创作中提供可恢复的故事工作台，先规划人物、场景和镜头，再定稿参考图，试拍前四镜后续拍。

**架构：** 独立 StoryWorkbench 组件承载新流程；故事规划接口不依赖 MySQL。浏览器 IndexedDB 保存多个项目及上传参考图，图片继续由现有图片服务保存到桌面。原有数据库系列入口保留。出图模型沿用已验证的 Sunburst，文本模型使用服务器配置。

## 边界

- 本轮优先故事，诗词工作台保持现有流程。
- 不把不同分镜当作同一张图片的修改版本；固定参考图只负责身份和场景设定。
- 同场景仅引用紧邻且成功的上一镜；换场景不携带上一镜背景。
- 角色参考图缺失时明确提示；失败停止连续批次，可单独重试。
- 更改故事后要求重新规划；重新规划前保留旧项目为可切换项目。
- 四镜试拍最多生成前四镜中尚未完成的镜头，继续生成跳过已完成镜头。
- 本地保存失败明确显示；不会称已保存。关闭抽屉不丢任务，任务进行时禁止切换项目或修改输入。

- [x] 3. 独立工作台：故事输入、自动/指定镜数、可编辑分镜、角色/场景参考上传或生成、试拍、继续和单镜重拍；IndexedDB 持久化并恢复项目和参考图。
