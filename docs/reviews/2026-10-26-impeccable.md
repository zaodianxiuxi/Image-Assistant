# Image Assistant 首轮界面审查

日期：2026-10-26。范围：首页、单图编辑区、故事抽屉、诗词工作台。

## 结论

保留既有电影创作室与纸上故事馆的视觉身份。优先修复键盘进入抽屉的问题，再改善手机主操作的可达性和长篇诗词编辑的导航。首轮完成安装、产品与设计文档、代码和浏览器审查；没有实施 UI 修复。

## 方法和边界

- 单一审查上下文完成代码、视觉和检测器核对；未启动独立子代理，不等同于隔离双评审。
- 浏览器使用本地前端开发服务。后端 3001 没有监听，因此页面显示等待配置/请求失败；没有调用文本、图片模型或数据库写接口。
- 查看了明亮、深色、暖灰、纸上四套主题的页面；窄屏重点检查明亮和纸上首页、纸上故事及诗词抽屉。桌面约 1280px，窄屏 390×844；有滚动条时内容宽约 375px。
- 故事为空项目；诗词工作台显示现有《咸阳城东楼》分析与六段提示词。未验证真实生成、批量任务取消、数据库恢复或完整导出流程。
- 使用只读 DOM 检查与截图。浏览器 evaluate 接口仅允许读取，未注入 Impeccable 检测覆盖层，也未启动 live 模式。
- 截图及检测器结果保存在同名目录。尺寸是本轮样本，不是所有设备的通用值。

## 应保留的优点

1. 电影分镜与纸上书页插画有产品语义，且标明示意用途；已有视觉身份无需整体替换。
2. 桌面输入、画布、工具分区明确，生成按钮与可滚动输入区分开，已有故事阶段和保存状态。
3. 已有主题变量、按钮焦点样式、减少动态效果支持、诗词进度提示和失败重试基础，不应在整理样式时丢失。

## 按优先级排序的问题

### P1 — 故事与诗词抽屉打开后，键盘焦点留在背景

**证据：** 点击“开始故事创作”后，document.activeElement 仍是首页入口，故事 dialog.contains(activeElement) 为 false。接着在入口按 Tab，焦点进入被遮挡的“定格一个想法”。打开诗词工作台后，焦点同样停留在背景工具按钮。

**位置：** src/StoryWorkbench.tsx:95、311；src/App.tsx:2135。已有 role=dialog 和 aria-modal，但没有对应的统一进入焦点、焦点循环和背景隔离机制。

**影响：** 键盘用户不能顺着可见抽屉开始操作，可能操作遮罩后的界面。建议作为下一轮第一个修复项。

**建议与验收：** 建立统一抽屉/弹窗焦点策略；打开时聚焦标题、首个输入或关闭按钮，Tab/Shift+Tab 保持在最上层弹窗，背景不可交互；关闭后回到原入口。覆盖嵌套预览与原生下拉菜单，避免 Escape 一次关闭多层。无需更改请求或数据结构。

### P2 — 纸上主题手机首页将单图创作排在很长的欢迎区之后

**证据：** 390×844 下，纸上首页画布容器约 1400px 高，提示词输入框顶部约 1775px，生成按钮约 2548px；明亮主题输入框约 340px，生成按钮约 1051px。两者均有滚动补救路径，但纸上主题的差异尤其明显。

**位置：** src/paper-theme.css:151–153；src/cinema-workspace.css 的 ≤850px 规则。纸上空画布的 order: -1 将整个欢迎区及图库前置。

**建议与验收：** 保留书页视觉，缩短移动欢迎区并给出可见的单图快捷入口；避免空图库占据主操作之前的大块空间。考虑让生成操作在手机编辑过程中保持易达。验证 390px 首页到单图输入、故事和诗词三条路径，以及有结果后的布局。

**证据图：** [纸上首页](2026-10-26-impeccable/paper-home-mobile.png)、[明亮首页](2026-10-26-impeccable/light-home-mobile.png)。

### P2 — 诗词分析与分镜之间缺少适合长内容的导航

**证据：** 当前样例的分析区含 44 个输入控件，390px 下约 4478px 高；主要动作位于约 y=947 的表单区。用户读到后面的分析与分镜时，需要反复长距离滚动。步骤指示存在，但不是跳转导航。

**位置：** src/App.tsx 的 .poetry-actions、.poetry-workflow、.poetry-analysis；相关样式在 src/styles.css 与 src/paper-theme.css。

**建议与验收：** 增加“原文 / 分析 / 分镜”锚点或分段导航，把背景、典故等次级内容按需展开，提供可定位的当前阶段操作。保留已编辑字段及自动保存语义。验证长诗、六到八段分镜、窄屏与键盘操作。

**证据图：** [诗词窄屏](2026-10-26-impeccable/paper-poetry-mobile.png)。

### P2 — 部分手机常用操作的点击区域偏小

**证据：** 明亮主题窄屏实际按钮高度：保存约 17px、添加编辑遮罩约 15.5px、刷新灵感 24px、主题切换 32px；纸上故事关闭按钮 32×32px。部分故事按钮 42px，与 44px 的差异较小，不列为主要问题。

**位置：** src/styles.css 的 .inline-action、.text-button、.hotlist-refresh、.icon-button，以及各工作台关闭按钮。

**建议与验收：** 优先扩大保存、关闭和主题切换的有效点击区域，保持视觉尺寸克制；手机主操作可按约 44px 的项目目标检查。这里是可用性建议，不据此宣称已完成 WCAG 审核或每个小按钮均违反标准。

### P3 — 故事工具入口的可见名称与可访问名称不同

**证据：** 右侧工具可见文案为“故事创作”，可访问名称为“打开系列创作”；抽屉内又有“已有数据库系列”，增加概念混淆。

**位置：** src/App.tsx 的 story-tool 按钮。

**建议与验收：** 统一新故事入口的名称，把数据库系列保留为独立且明确的功能。检查可见文本、aria-label、title 与实际打开的工作台一致。

## 认知负担与使用过程

- 新用户：欢迎区能激发创作，但纸上手机首页对“只生成一张图”的用户路径较长。
- 连续创作者：故事阶段和保存状态有帮助；诗词分析的一次性长表单使跨段修改成本较高。
- 键盘用户：弹窗焦点外漏是本轮最明确的障碍。
- 手机上手：工具入口能发现，但小按钮、长表单和主操作位置增加寻找与点击成本。

操作型页面的重点应是可预测、可恢复、少走回头路。故事试拍、已有图片、失败恢复等完整情绪过程本轮未运行，不作体验结论。
