# 后续方向

本文记录 Image Assistant 已确认但尚未实施的演进方向。当前优先保证本地生成、预览和画幅流程稳定；以下事项不影响现有接口使用。

## 优先级 P0：图片持久化

### MinIO 对象存储与元数据

- 使用 MinIO 保存生成图、编辑结果和必要的缩略图，避免上游临时图片 URL 失效后无法再次展示。
- 使用 SQLite 记录图片 ID、对象键、提示词、画幅、操作类型、创建时间、文件大小和来源请求 ID。
- 图片访问由本地服务签发短期预签名 URL；不开放匿名写入，也不把 MinIO 访问密钥放入浏览器。
- 提供本地开发 Docker Compose 配置、桶初始化和 `.env.example` 配置项。

### 持久化历史记录

- 将当前浏览器会话内的历史记录迁移为服务端分页接口。
- 支持按时间查看、查看完整提示词、下载和单张删除。
- 明确保留期限、容量上限和自动清理规则，避免本地磁盘或对象存储无限增长。

## 优先级 P1：图片可靠性与体验

- 对上游返回的远程图片 URL 增加服务端安全代理或在生成完成时直接转存 MinIO。
- 预览弹层增加缩放、适应宽度、适应高度和原始尺寸查看；保留 Escape 和点击遮罩关闭。
- 历史缩略图可根据真实画幅动态调整展示框，继续保证完整显示而不裁切。
- 对生成失败、图片加载失败和 URL 失效提供可追踪的请求 ID 与可操作的恢复提示。

## 优先级 P2：创作与内容管理

- 热榜提示词增加分类筛选、收藏、复制、搜索和本地自定义提示词。
- 静态精选集合支持通过版本化 JSON 或后台管理更新，继续保持“按日稳定随机”的展示规则。
- 保存常用画幅、主题和生成参数预设，减少重复设置。

## 实施边界

- MinIO 与数据库接入应作为独立功能实施，先补齐存储失败、签名 URL 过期和清理策略的测试。
- 不将 API Key、MinIO 密钥、原始上传图片或用户生成内容提交到 Git 仓库。
- 上线多用户能力前，需要补充身份认证、访问隔离、请求限流和内容审计策略。
